How a Job Moves

Every request at Porto followed the same route, from the first report to the finished fix. Deciding when something was ready was never my call alone.

STEP 01

Intake

A user runs into a problem and reports it along with the data behind it. The IT BA or the IT Manager decides how urgent it is, then passes it to a developer to fix.

STEP 02

Diagnose & Build

I read the evidence before touching any code, because the hard bugs were rarely where the error message pointed. Most came down to the same handful of causes: a field left empty, data that never got pulled through, a duplicate record where there should have been one, or a value read from the wrong source.

STEP 03

Verify

The Business Analyst tests the result against what the business actually needs, not against what I assumed. If it falls short, it comes back to me, gets fixed, and goes back for testing again. Only once it passes does it reach real users.
